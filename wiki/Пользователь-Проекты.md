# Пользователь-Проекты

Проект объединяет находки, настройки источника, участников, токены и записи приёма отчётов. [Проектная роль](Пользователь-Интерфейс) определяет доступные действия. Команда и видимость проекта не заменяют выдачу роли участнику.

## Открытие проекта

Роль: просмотр и выше.

1. Откройте «Проекты». При необходимости задайте поиск по имени, тегу или репозиторию, фильтры статуса, команды, SLA, покрытия и тегов.
2. Выберите представление карточками или списком. В списке нажмите название проекта для открытия его страницы; нажатие строки открывает краткий обзор. Карточка в представлении сеткой переводит непосредственно к находкам проекта.
3. На странице проекта выберите вкладку согласно таблице.

Проверка результата: в обзоре показаны название и идентификатор нужного проекта. Кнопка «Перейти к находкам» на вкладке «Находки» открывает список с фильтром этого проекта.

| Вкладка | Содержимое | Права |
|---|---|---|
| Обзор | Название, описание, статус, тип источника, идентификатор | Просмотр и выше |
| Находки | Переход к общей таблице с фильтром проекта | Просмотр и выше |
| Участники | Список участников, добавление, изменение роли, исключение | Администратор проекта или глобальный администратор |
| Настройки | Основные параметры, источник, доступ, SLA | Администратор проекта или глобальный администратор; смена владельца дополнительно ограничена владельцем или глобальным администратором |
| Токены | Метаданные API-токенов и управление ими | Просмотр списка — просмотр и выше; создание и отзыв — администратор проекта или глобальный администратор |
| Сканы | Принятые через API сканы, их состояние и находки | Просмотр и выше |

Список проектов запрашивает ограниченную порцию данных; не трактуйте локальные счётчики фильтров как полный инвентарный отчёт. Закрепление хранится у проекта, а не в личных избранных пользователя.

## Создание проекта

Роль: любой аутентифицированный пользователь после обязательной смены пароля. Создатель получает роль администратора проекта; выбранному владельцу также назначается эта роль.

1. Нажмите «Новый проект».
2. На шаге «Основы» задайте название, при необходимости описание, цвет и теги; выберите шаблон. В этой форме название допускает русские и латинские буквы, цифры, пробелы, дефис и подчёркивание, длина — от 3 до 64 символов. Проверьте, что форма не сообщает о занятом идентификаторе `slug`.
3. На шаге «Источник» для создания пустого проекта нажмите «Пропустить и настроить позже →».
4. На шаге «Команда и SLA» проверьте владельца, при необходимости выберите команду и параметры SLA. Не рассчитывайте на отправку приглашений из мастера: сервер принимает поле приглашений, но не реализует их отправку.
5. Нажмите кнопку создания проекта.

Проверка результата: мастер закрывается и открывается вкладка «Токены» нового проекта. В «Обзоре» проверьте название, в «Участниках» — назначенные роли. Результаты сканирования загружайте отдельно через [Импорт](Пользователь-Импорт-результатов).

### Ограничения шага «Источник»

«Подтвердить подключение» для Git отмечает заполнение адреса, но не проверяет доступ к репозиторию и не запускает сканер. Поле «Автосканирование при push» сохраняется как настройка проекта; исполнитель сканирования в этом сценарии отсутствует.

Выбор SARIF/JSON внутри мастера не отправляет содержимое файла на импорт: предварительные числа рассчитываются по размеру файла. Они не являются результатом разбора отчёта. Пример webhook и выпуск токена во временный проект также не заменяют рабочую вкладку «Токены». Для реального приёма отчётов используйте страницу «Импорт» либо настроенную внешнюю интеграцию.

## Изменение проекта

Роль: администратор проекта или глобальный администратор. Передача владения разрешена только текущему владельцу с доступом к настройкам либо глобальному администратору.

1. Откройте вкладку «Настройки».
2. Измените нужные поля. Сохранение основных параметров не меняет UUID проекта.
3. Нажмите «Сохранить настройки».

Проверка результата: появляется сообщение «Настройки проекта сохранены». Перезагрузите страницу и убедитесь, что значения сохранились. При передаче владения прежний владелец не исключается автоматически из участников.

| Группа | Доступные параметры | Ограничение интерпретации |
|---|---|---|
| Основные параметры | Название, `slug`, описание, цвет, теги, статус | Статус проекта не является статусом его находок |
| Источник | Тип источника; для Git — провайдер, URL, ветка, признак автосканирования | Сохранение параметров не запускает сканер |
| Доступ | Владелец, команда, видимость | Для доступа пользователя требуется проектное назначение |
| SLA | Сроки по критичности и число дней до уведомления | Наличие поля уведомления не подтверждает отправку уведомлений |

В меню строки списка доступны переименование, дублирование, архивирование, настройки и переход к экспорту. Переименование, архивирование и звёздочка закрепления требуют администратора проекта либо глобального администратора. Дублирование доступно пользователю, который может просмотреть исходный проект и создать новый: копируются передаваемые формой основные параметры, но не находки, участники, сканы и токены.

1. Найдите проект в представлении списком и выберите нужное действие в меню строки либо нажмите звёздочку для закрепления. Права на каждое действие приведены выше.
2. Для переименования или дублирования задайте имя в запросе браузера.

Проверка результата: после перезагрузки списка видны новое имя, состояние звёздочки либо статус «Архивный». При дублировании открывается проект с другим UUID и без скопированных находок.

Пункт «Экспорт» лишь открывает находки проекта: сам файл выгружается на странице [Экспорт отчётов](Пользователь-Экспорт-отчётов), для чего достаточно роли просмотра.

## Управление участниками

Роль: администратор проекта или глобальный администратор.

1. Откройте «Участники» и нажмите «Добавить участника».
2. Найдите существующего пользователя, выберите его и нажмите «Добавить». Форма назначает роль «Триаж».
3. При необходимости нажмите «Изменить роль» рядом с участником. Кнопка переводит администратора проекта в «Триаж», а участника с другой ролью — в администратора проекта. Выбрать роль «Просмотр» этой кнопкой нельзя.

Проверка результата: участник отображается в списке с ожидаемой ролью после перезагрузки. Сервер не разрешает понизить последнего администратора проекта.

Исключение участника прекращает его доступ по данному проектному назначению; оно не удаляет учётную запись.

1. Проверьте адрес пользователя в строке участника.
2. Нажмите «Удалить».

Проверка результата: участник исчезает из списка. Последнего администратора проекта исключить нельзя. У глобального администратора доступ сохраняется независимо от проектного назначения.

## API-токены

Роль для создания и отзыва: администратор проекта или глобальный администратор. Просмотр списка доступен роли просмотра и выше.

1. Откройте «Токены» и нажмите «Создать токен».
2. Задайте имя, выберите предлагаемые права `scans:write` и/или `findings:read`, срок 30 дней, 90 дней либо «Без срока».
3. Нажмите «Создать» и скопируйте секрет из окна результата в предназначенное для него хранилище. Полное значение выдаётся при создании; список содержит только префикс.

Проверка результата: новый токен виден в списке с выбранными правами и сроком. Работоспособность конкретной интеграции проверяется отдельным запросом этой интеграции; создание токена само по себе не отправляет отчёт.

Отзыв деактивирует токен; восстановление прежнего секрета через интерфейс не предусмотрено. До отзыва подготовьте замену для использующих его интеграций.

1. Найдите токен по имени и префиксу, нажмите «Отозвать».
2. Подтвердите отзыв в диалоге.

Проверка результата: токен скрыт из обычного списка и отображается при включении «Показать отозванные».

## Просмотр сканов

Роль: просмотр и выше.

1. Откройте вкладку «Сканы», при необходимости задайте ветку, сканер и статус.
2. Нажмите строку скана. Просмотрите счётчики импортированных и обновлённых находок, список находок, ветку и коммит. При наличии ссылки на задание CI откройте её для проверки внешнего запуска.
3. Для перехода к следующей порции списка нажмите «Загрузить ещё», если кнопка отображается.

Проверка результата: открывается окно «Детали скана» с выбранными метаданными. Статусы «Выполняется», «Завершён» и «Ошибка» относятся к записи приёма отчёта, а не к запуску сканера платформой. Импорт со страницы «Импорт» не создаёт такую запись скана.

## Удаление проекта

Роль: владелец проекта либо глобальный администратор.

Удаление необратимо средствами интерфейса: удаляются проект и его находки. Для сохранения данных выберите архивирование; для возможности восстановления предварительно обеспечьте [резервную копию](Администратор-Резервное-копирование).

1. В меню строки нужного проекта выберите «Удалить проект».
2. Проверьте имя в предупреждении и подтвердите удаление.

Проверка результата: после обновления списка проект отсутствует; прежняя страница проекта больше не открывает его данные.
