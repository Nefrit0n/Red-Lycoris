# Быстрый-старт-Первый-импорт

После [развёртывания](Быстрый-старт-Развёртывание) создайте тестовый проект и загрузите одну синтетическую находку через интерфейс. Для этого не требуются сканер, CVE или внешние базы обогащения.

Выполняйте сценарий под первоначальным глобальным администратором. В дальнейшем ручной импорт доступен пользователю с проектной ролью `triager` или выше, а просмотр находок — с ролью `viewer` или выше.

## 1. Создайте проект

1. Откройте «Проекты» и нажмите «Создать проект».
2. На шаге «Основы» задайте название «Проверка импорта» и проверьте предложенный идентификатор проекта. На шаге «Источник» выберите «Пропустить и настроить позже».
3. На шаге «Команда и SLA» оставьте владельцем текущего администратора и нажмите «Создать проект».

Проверка результата: интерфейс открывает созданный проект; в сетевой панели браузера `POST /api/v1/projects` возвращает 201 и `data.id`. Проект доступен в списке проектов. Подключение репозитория для тестового импорта не требуется.

## 2. Подготовьте файл

1. Создайте в текстовом редакторе файл `quickstart.json` в UTF-8 и вставьте JSON:

~~~json
{
  "source_type": "quickstart",
  "findings": [
    {
      "kind": "sast",
      "title": "Тестовая находка быстрого старта",
      "description": "Синтетическая запись для проверки импорта",
      "severity": "medium",
      "confidence": "high",
      "status": "open",
      "file_path": "quickstart/example.go",
      "line_start": 10,
      "line_end": 10,
      "rule_id": "red-lycoris-quickstart-demo"
    }
  ]
}
~~~

2. Проверьте, что сохранён именно JSON без Markdown-ограждений и расширения `.txt`.

Проверка результата: файл содержит непустой source_type и один объект в findings; он готов к выбору на странице импорта. Полный справочник полей — [Generic JSON](Интеграции-Формат-Generic-JSON).

## 3. Загрузите находку

1. Откройте «Импорт» (`http://localhost:3000/import`).
2. Перетащите quickstart.json в область «Файлы» либо выберите его через диалог.
3. В поле «Целевой проект» выберите «Проверка импорта» и нажмите «Импортировать 1 файл».

Проверка результата: в карточке «Импорт завершён» для новой находки отображаются `+1 импортировано`, `~0 обновлено`, без ошибок. Сервер определяет формат как generic. В сетевой панели запрос `POST /api/v1/import?project_id=<UUID>` возвращает HTTP 200, а тело содержит:

~~~json
{
  "format": "generic",
  "imported": 1,
  "updated": 0,
  "errors": null
}
~~~

Если эта же тестовая находка уже есть в экземпляре, возможны `imported: 0` и `updated: 1`. Уникальность fingerprint глобальная, поэтому создание второго проекта не гарантирует новую копию той же находки. Подробности — [дедупликация](Система-Дедупликация).

## 4. Проверьте находку и повторный импорт

1. Откройте список находок, выберите тестовый проект и найдите «Тестовая находка быстрого старта».
2. Откройте карточку. Сравните категорию SAST, критичность medium, статус open, путь quickstart/example.go и строку 10 с файлом.
3. Вернитесь на страницу импорта. При необходимости нажмите «Импортировать ещё», выберите тот же файл и проект и повторите загрузку.

Проверка результата: второй импорт показывает `+0 импортировано`, `~1 обновлено` без ошибок. В проекте остаётся одна тестовая находка. Этот способ загрузки не создаёт запись CI-скана: проверяйте список находок, а не вкладку сканов.

## Если результат отличается

| Симптом | Что проверить | Ожидаемый результат после исправления |
|---|---|---|
| Кнопка импорта недоступна | Выбран ли проект и прошёл ли файл проверку | Кнопка доступна для одного файла |
| Ошибка разбора | Содержимое файла, кавычки, отсутствие Markdown и постороннего текста | Формат generic, без ошибок |
| 401 или 403 | Вход и право triager на выбранный проект; завершена ли обязательная смена пароля | Запрос импорта проходит авторизацию |
| HTTP 200, но imported и updated равны нулю | Поле errors в ответе: ручной импорт может завершиться частично | После исправления записи сумма счётчиков равна 1 |
| Находка не видна | Фильтры и выбранный проект; не импортировалась ли та же запись ранее в другой проект | Карточка находится по названию и соответствует источнику |
| Нет данных NVD/EPSS/KEV | Тестовый отчёт не содержит CVE; планировщик отключён в сценарии запуска | Сам импорт и просмотр работают независимо от внешнего обогащения |

Для загрузки реального отчёта выберите [поддерживаемый формат](Интеграции-Поддерживаемые-сканеры). Для CI выпустите [PAT проекта](Интеграции-API-токены) и подключите [GitLab CI](Интеграции-GitLab-CI) или [GitHub Actions](Интеграции-GitHub-Actions). Дальнейшая работа в интерфейсе описана в [руководстве пользователя](Пользователь-Интерфейс).
