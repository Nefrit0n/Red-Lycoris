# Разработка-Локальное-окружение

Локальная разработка использует PostgreSQL и Redis из Docker Compose, а сервер и интерфейс можно запускать непосредственно на рабочей станции. Конфигурация сервера читается из переменных окружения; значения по умолчанию рассчитаны на PostgreSQL и Redis по `localhost`.

## Предварительные требования

| Компонент | Назначение | Подтверждение в репозитории |
|---|---|---|
| Go 1.25 | Сборка и запуск backend | Директива `go` в `backend/go.mod` |
| Node.js 20 | Локальный frontend и CI | `setup-node` в workflow PR |
| npm с lock-файлом | Установка зависимостей frontend | `frontend/package-lock.json`, команда `npm ci` в CI |
| Docker Engine и Compose plugin | PostgreSQL, Redis и полный Compose-стек | `docker-compose.yml`, Makefile |

Перед первым запуском скопируйте пример конфигурации и задайте пароль bootstrap-администратора. Не коммитьте `.env`.

```bash
cp env.example .env
```

В PowerShell используйте:

```powershell
Copy-Item env.example .env
```

Проверьте результат: файл `.env` существует, а значения `POSTGRES_PASSWORD` и `BOOTSTRAP_ADMIN_PASSWORD` не оставлены производственными значениями по умолчанию.

## Инфраструктура и backend

1. Запустите PostgreSQL и Redis из корня репозитория.

   ```bash
   docker compose up -d postgres redis
   ```

2. Проверьте, что оба контейнера стали healthy.

   ```bash
   docker compose ps
   ```

3. Запустите сервер из каталога backend.

   ```bash
   cd backend
   go run ./cmd/server
   ```

При запуске сервер ожидает PostgreSQL и Redis, применяет миграции до открытия HTTP-порта, создаёт bootstrap-администратора только при пустой таблице `users`, затем слушает `SERVER_HOST:SERVER_PORT`. Остановка через `Ctrl+C` завершает HTTP-сервер и фоновые задачи.

Проверьте результат отдельным терминалом:

```bash
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
```

Оба маршрута должны вернуть успешный HTTP-статус после готовности PostgreSQL и Redis. Если порт или хост изменены в конфигурации, используйте фактический адрес.

## Frontend

1. В новом терминале перейдите в каталог frontend и установите зависимости из lock-файла.

   ```bash
   cd frontend
   npm ci
   ```

2. Запустите Vite.

   ```bash
   npm run dev
   ```

3. Откройте адрес, который напечатает Vite.

Проверьте результат: Vite сообщает локальный URL без ошибки сборки, а страница входа доступна в браузере. При раздельном запуске frontend обращается к API согласно `VITE_API_URL` и настройкам Vite; проверьте сетевые запросы браузера, если сервер запущен не на `localhost:8080`.

## Полный Compose-стек

Для проверки контейнерной сборки используйте цель Makefile или команду Compose:

```bash
make dev
```

Команда запускает `docker compose up --build` и занимает терминал. Для фонового запуска выполните `make dev-d`.

Проверьте результат:

```bash
docker compose ps
```

Сервисы PostgreSQL, Redis, backend и frontend должны быть запущены. Состояние и логи контейнеров не заменяют проверки API `/healthz` и `/readyz`.

## Полезные команды

| Команда | Действие |
|---|---|
| `make logs` | Следит за логами всех сервисов Compose |
| `make logs-api` | Следит за логами backend |
| `make stop` | Останавливает Compose без удаления volumes |
| `make build` | Собирает образы без запуска |
| `make prod` | Запускает production overlay в фоне |
| `make clean` | Останавливает Compose и удаляет volumes |

> **Предупреждение.** `make clean` вызывает `docker compose down -v` и безвозвратно удаляет локальные volumes PostgreSQL и Redis. Не выполняйте его, если в них есть нужные данные.

Проверьте результат после `make stop` или `make clean` командой `docker compose ps`: запущенных сервисов быть не должно. После `make clean` список `docker volume ls` не должен содержать volumes данного Compose-проекта.
