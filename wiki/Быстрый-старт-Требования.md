# Быстрый-старт-Требования

Этот сценарий позволяет проверить локальную установку на одной тестовой находке: [разверните приложение](Быстрый-старт-Развёртывание), затем выполните [первый импорт](Быстрый-старт-Первый-импорт). Запуск сканера для этой проверки не требуется.

## Что подготовить

| Компонент | Требование для сценария |
|---|---|
| Узел | Среда с работающим Docker Engine и возможностью запуска Linux-контейнеров |
| Docker Compose | Plugin с командой `docker compose`; минимальная поддерживаемая версия проектом не закреплена |
| Исходники | Копия репозитория, включая backend, frontend и migrations; Git нужен для клонирования |
| Командная оболочка | Команды ниже рассчитаны на Bash; curl используется для HTTP-проверки |
| Браузер | Для входа и импорта через интерфейс; минимальные поддерживаемые версии не закреплены, см. [требования к рабочему месту](Администратор-Требования-к-рабочему-месту) |
| Сеть для сборки | Доступ к реестрам базовых образов, источникам Go-модулей и npm-пакетов либо их настроенным зеркалам |
| Порты узла | При стандартной конфигурации свободны 3000, 8080, 5432 и 6379 |
| Данные | Новый тестовый экземпляр без существующих пользователей и рабочих данных |

Go и Node.js на узле для этого сценария не нужны: backend и frontend собираются по Dockerfile. PostgreSQL и Redis запускаются образами `postgres:16-alpine` и `redis:7-alpine`. Данные размещаются в именованных томах Docker.

Нормативы CPU, RAM и диска для разных нагрузок не установлены кодом. Лимиты контейнеров в Compose не являются подтверждённым минимумом ресурсов всего узла и не учитывают расход сборки. Для подбора ресурсов используйте [требования к инфраструктуре](Администратор-Требования-к-инфраструктуре).

Базовый Compose публикует PostgreSQL и Redis на узле; пароль Redis не задан. Выполняйте этот сценарий на изолированном тестовом узле с доступом только из доверенной сети. Для эксплуатации подготовьте [безопасную сетевую конфигурацию](Администратор-Безопасная-сетевая-конфигурация) и следуйте [инструкции администратора](Администратор-Установка-Docker-Compose).

## Проверка инструментов

1. Выполните в терминале:

~~~bash
docker version
docker compose version
git --version
curl --version
~~~

2. Проверьте вывод перед продолжением.

Проверка результата: `docker version` выводит разделы Client и Server без ошибки подключения, Compose, Git и curl выводят свои версии. Если Docker Server недоступен, запустите Docker и повторите проверку. Следующий шаг — [развёртывание](Быстрый-старт-Развёртывание).
