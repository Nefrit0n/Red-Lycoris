# Быстрый-старт-Развёртывание

Процедура рассчитана на новый локальный экземпляр и стандартные порты. Сначала проверьте [требования](Быстрый-старт-Требования). Все команды выполняйте в Bash; после получения исходников оставайтесь в корне репозитория.

## 1. Получите исходники и задайте параметры

1. Клонируйте репозиторий, если у вас ещё нет его копии:

~~~bash
git clone https://github.com/Nefrit0n/Red-Lycoris.git
cd Red-Lycoris
~~~

2. Создайте файл окружения. Если `.env` уже существует, сначала проверьте его: команда ниже намеренно откажется перезаписывать файл.

~~~bash
test ! -e .env && cp env.example .env
~~~

3. Откройте `.env` в редакторе и задайте:

| Переменная | Значение для этого сценария |
|---|---|
| `POSTGRES_PASSWORD` | Собственный уникальный пароль вместо значения примера; для этого сценария используйте длинную случайную строку из букв и цифр, чтобы не требовалось кодирование в URL подключения |
| `BOOTSTRAP_ADMIN_EMAIL` | Ваш адрес; можно оставить `admin@localhost` для локального теста |
| `BOOTSTRAP_ADMIN_PASSWORD` | Собственный первоначальный пароль вместо `admin` |
| `BOOTSTRAP_ADMIN_FORCE_PASSWORD_CHANGE` | `true`; ручная смена всё равно входит в процедуру ниже |
| `FRONTEND_TARGET` | `development`, как в env.example |
| `ENRICHMENT_ENABLED` | `false`, чтобы не запускать планировщик синхронизации внешних баз во время первого знакомства |
| `LOG_LEVEL` | `info`, чтобы видеть сообщения запуска |

Имена БД и пользователя оставьте стандартными. В этом Compose адрес PostgreSQL для backend строится из POSTGRES-переменных; отдельная DATABASE_URL из `.env` туда не подставляется. Изменение POSTGRES_PASSWORD после инициализации тома не меняет пароль уже созданного пользователя БД.

ENRICHMENT_ENABLED=false отключает запуск планировщика, но не является сетевой блокировкой и не отключает весь код обогащения. Для закрытого контура используйте [отдельную инструкцию](Администратор-Работа-в-закрытом-контуре).

4. Проверьте конфигурацию без вывода значений секретов:

~~~bash
docker compose config --quiet
~~~

Проверка результата: команда завершается с кодом 0 без сообщения об ошибке. Она проверяет конфигурацию Compose, но не доступность БД и не стойкость паролей.

## 2. Соберите и запустите приложение

Запуск backend автоматически применяет миграции к указанной БД. Для существующей установки с данными сначала выполните [резервное копирование](Администратор-Резервное-копирование) и используйте [порядок обновления](Администратор-Обновление).

1. Запустите сервисы:

~~~bash
docker compose up --build -d
~~~

2. Дождитесь запуска backend и проверьте состояние:

~~~bash
docker compose ps
docker compose logs --tail=100 backend
curl --fail --silent --show-error http://localhost:8080/healthz
curl --fail --silent --show-error http://localhost:8080/readyz
curl --fail --silent --show-error --output /dev/null http://localhost:3000/
~~~

Проверка результата: все сервисы запущены; в журнале backend есть `migrations applied` и `starting server`, а на новой БД — `bootstrap admin created`. `healthz` возвращает `ok`, `readyz` — `{"status":"ready"}`, запрос frontend завершается без ошибки. Не ограничивайтесь пометкой healthy в Compose: healthcheck backend вызывает CLI `admin --help`, а не проверяет готовность HTTP API.

Если готовности нет, выполните `docker compose logs --tail=100 postgres redis backend frontend` и найдите ошибку запуска. Повторяйте HTTP-проверку после её устранения. Не запускайте отдельную команду миграции поверх работающего сервера: миграции уже входят в его запуск.

## 3. Войдите и смените пароль

1. Откройте `http://localhost:3000` и войдите с BOOTSTRAP_ADMIN_EMAIL и BOOTSTRAP_ADMIN_PASSWORD.
2. Откройте `http://localhost:3000/auth/change-password`. В текущем bootstrap-коде флаг принудительной смены не записывается в учётные данные, поэтому автоматического перенаправления может не быть.
3. Введите текущий и новый пароль и нажмите «Сменить пароль». Учтите перед отправкой: смена завершает другие сессии этого пользователя.
4. Выйдите и войдите с новым паролем.

Проверка результата: вход с новым паролем успешен, открывается приложение. В сетевой панели браузера запрос `POST /api/v1/auth/change-password` имеет статус 200. Изменение BOOTSTRAP_ADMIN_PASSWORD в `.env` не заменяет эту процедуру: bootstrap создаёт пользователя только при пустой таблице users.

Далее выполните [первый импорт](Быстрый-старт-Первый-импорт).

## Остановка и повторный запуск

Команды ниже сохраняют именованные тома. `make clean` и `docker compose down -v` удаляют тома с данными; для обычной остановки не используйте их.

1. Остановите экземпляр:

~~~bash
docker compose down
docker compose ps
~~~

Проверка результата: список запущенных сервисов этого Compose-проекта пуст.

2. Для продолжения работы выполните:

~~~bash
docker compose up -d
curl --fail --silent --show-error http://localhost:8080/readyz
~~~

Проверка результата: после завершения запуска readyz возвращает ready, вход работает с изменённым паролем, ранее созданные проекты сохранены.
