# Интеграции-Поддерживаемые-сканеры

Формат определяется по содержимому, независимо от расширения файла и поля `scanner` в CI-загрузке. Детектор проверяет парсеры в порядке строк таблицы и использует первый совпавший. Ошибка выбранного парсера не запускает следующий.

## Форматы и ограничения

| Сканер или формат | Формат и признак распознавания | Парсер | Особенности и ограничения |
|---|---|---|---|
| Solar appScreener | SARIF: идентификатор appScreener в driver первого run, версия `2.1.0` или SARIF в `$schema` | `appscreener` | Разделяет результаты на SCA по `properties.x-origin` или `ruleId: SCA`, остальные — SAST. Для SCA извлекает компонент из первой logical location, CVE из `scaId`/aliases, PURL/CPE, CWE. `versionEnd` становится исправленной версией только при исключённой верхней границе. Для SAST учитывает `x-severity`, `x-classifications`, snippet. HTML описания очищается. Определение инструмента по первому run распространяется на весь файл |
| SARIF | JSON, `$schema` содержит `sarif` либо `version: "2.1.0"` | `sarif` | Читает runs/results, правила, первую location, snippet, CVE/CWE, package/web metadata. Категория выводится по содержимому и подсказке имени driver. Это выборочное отображение SARIF в модель находки, а не сохранение всех полей стандарта. Для SCA проверьте наличие package metadata |
| Trivy | JSON, `SchemaVersion`, непустой `Results`; хотя бы одна секция содержит массив Vulnerabilities, Misconfigurations или Secrets | `trivy` | `Class: os-pkgs/lang-pkgs` → SCA; `config` → IaC; `secret` → secrets. Прочие классы не обрабатываются. Передаёт PURL, версию пакета, исправление, CWE. SCA использует отдельный fingerprint с данными пакета, target и artifact; изменение target может создать новую находку. Отчёт без извлечённых находок возвращает ошибку парсинга |
| Semgrep | JSON с непустым `results` и `check_id` первого результата | `semgrep` | Всегда SAST; переносит правило, путь, строки, snippet и CWE из metadata. `INFO` → low, `WARNING` → medium, `ERROR` → high или critical при confidence HIGH. Пустой results не распознаётся; поддержка этого JSON не означает обработку всех продуктов Semgrep |
| gosec | JSON с полем `Issues`, либо сочетанием `GosecVersion` и `Stats` | `gosec` | SAST; правило, CWE, код, файл. `line` разбирается как одно положительное целое, диапазон строк не поддержан; если line не разобран, используется column. HIGH/MEDIUM/LOW → high/medium/low |
| TruffleHog v3 | NDJSON, одиночный объект либо непустой массив; в первом объекте нужны `SourceMetadata.Data`, `DetectorName` и DecoderName либо trufflehog в SourceName | `trufflehog` | Secrets; извлекает метаданные Git/Filesystem/Github и предусмотренных дополнительных источников. Verified → critical/confirmed, иначе high/high. Из Raw/RawV2 рассчитывает secret fingerprint, описание содержит маскированное представление. Пустой файл или массив не распознаётся |
| Gitleaks | JSON-массив либо конверт `findings`, `leaks`, `results`; в первом элементе нужны RuleID и Match либо Secret | `gitleaks` | Secrets, severity high и confidence high; переносит путь, строки, commit и правило. Secret используется для secret fingerprint, описание маскирует значение. Commit не обязателен для распознавания. Пустые массивы не распознаются |
| Checkov | JSON-объект или массив секций с check_type, массивами checks/parsing_errors либо сведениями summary | `checkov` | Только `failed_checks`, категория IaC; passed/skipped и parsing_errors не становятся находками. Переносит ресурс, правило, строки и код. Неизвестная или отсутствующая severity → medium. Поддерживаются резервные поля пути и расположения |
| OWASP ZAP | JSON с `@programName: "ZAP"` и массивом `site` | `zap` | DAST; результат на каждый instance, а без instances — на site. URL, method, param, evidence, CWE и pluginid сохраняются; текстовые HTML-теги описания удаляются. Наличие только site без имени ZAP недостаточно. Разные instances могут затем объединиться по глобальному fingerprint |
| Grype | JSON с `matches`; descriptor.name grype либо узнаваемая структура matches | `grype` | SCA, пакет/версия/PURL, CWE, исправленная версия и путь. Выбираются первая непустая исправленная версия и первый подходящий путь. Пустой matches распознаётся; ручной импорт разрешает пустой результат именно этого парсера |
| Собственный сканер | JSON-конверт с непустой строкой `source_type` и массивом `findings` | `generic` | Проверяется последним. Поля, типы, примеры категорий и нормализация описаны в [Generic JSON](Интеграции-Формат-Generic-JSON) |

Для Trivy и Grype выбирайте нативный JSON: соответствующие парсеры явно извлекают метаданные пакетов. При использовании SARIF проверьте, что экспортёр передал эти сведения. Наличие SBOM у сканера само по себе не делает его входным форматом: отдельных парсеров CycloneDX и SPDX в детекторе нет.

Пустой отчёт не обрабатывается одинаково для всех инструментов. CI-обработчик допускает ноль находок, если парсер распознал отчёт и завершился успешно; ручной импорт отклоняет ноль, кроме Grype. Не заменяйте повреждённый отчёт пустым Generic, чтобы сделать задание успешным.

## Проверка нового источника

1. Выгрузите небольшой отчёт из используемой версии сканера. Проверьте характерные поля по таблице.
2. Загрузите отчёт с PAT тестового проекта через [CI API](Интеграции-Обзор). Для ручной загрузки используйте сессию пользователя с ролью `triager` или выше.
3. Откройте находки и сравните категорию, критичность, правило, путь или компонент с исходным отчётом. Отдельно проверьте отчёт без находок и повторную загрузку.

Проверка: выбран ожидаемый парсер, `imported + updated` соответствует числу извлечённых элементов, поля не потеряны. Число элементов исходного отчёта может отличаться от числа уникальных находок из-за разворачивания ZAP instances или дедупликации. HTTP 200 сам по себе не доказывает полноту переноса.
