# README

Этот каталог — единственный редактируемый источник GitHub Wiki Red Lycoris. Workflow [wiki.yml](https://github.com/Nefrit0n/Red-Lycoris/blob/main/.github/workflows/wiki.yml) синхронизирует его с отдельным Git-репозиторием Wiki при push в `main` с изменением `wiki/**`.

Не редактируйте страницы через веб-интерфейс GitHub Wiki: следующая синхронизация перезапишет такие изменения, включая созданные там страницы. Редактируйте Markdown в этом каталоге, проверьте diff и отправьте его обычным pull request.

## Имена и ссылки

Все пользовательские страницы лежат непосредственно в `wiki/` и называются `Раздел-Название-страницы.md`. Первая строка страницы — H1, совпадающий с именем файла без `.md`.

Ссылка на Wiki-страницу использует имя файла без расширения:

```markdown
[Обновление](Администратор-Обновление)
```

Ссылки на файлы основного репозитория используйте только как абсолютные GitHub URL:

```markdown
[OpenAPI](https://github.com/Nefrit0n/Red-Lycoris/blob/main/backend/api/openapi.yaml)
```

Не создавайте подкаталоги: GitHub Wiki использует плоскую структуру. `_Sidebar.md` и `_Footer.md` — служебные файлы GitHub Wiki; поддерживайте навигацию при добавлении пользовательской страницы.

## Публикация

Workflow сначала пробует `GITHUB_TOKEN`. Такой токен ограничен репозиторием, в котором исполняется workflow, а GitHub Wiki — отдельный репозиторий `<owner>/<repo>.wiki.git`; запись этим токеном может быть запрещена. Если запуск не может клонировать или push в Wiki, создайте секрет Actions `WIKI_PUSH_TOKEN` с токеном, которому разрешены чтение и запись Wiki основного репозитория. При наличии этот секрет имеет приоритет над `GITHUB_TOKEN`.

Проверьте результат после merge: workflow `Publish Wiki` завершился успешно, а commit `docs(wiki): sync from main` появился в истории Wiki. При удалении Markdown-файла из этого каталога синхронизация удалит соответствующий файл Wiki.
