# Администратор-Параметры-конфигурации

Справочник охватывает все переменные `config.go` и `env.example`, включая закомментированные, а также обнаруженные прямые чтения переменных в серверном коде. Параметры Compose, сборки и служебных скриптов отделены от конфигурации backend. Значения таблиц — значения кода, а не рекомендуемые секреты для эксплуатации.

¹ <!-- TODO: уточнить --> Версии введения переменных не установлены достоверно. История Git содержит прежнюю реализацию платформы и теги, не совпадающие с текущим `VERSION`; наличие имени в старом теге не подтверждает неизменность его смысла. В колонке не подменяется версия введения текущей версией приложения.

## Правила чтения

При прямом запуске backend читает окружение процесса и не загружает `.env` самостоятельно. Пустые строки для `getEnv` заменяются значениями по умолчанию. Некорректные логические значения и длительности также заменяются значениями по умолчанию без ошибки запуска. Для `ENRICHMENT_ENABLED` включением считается только точная строка `true`.

Файл `.env` при запуске Compose служит источником подстановок. Переменная попадает в контейнер только при соответствующей настройке `environment` или `env_file`; в поставке общего `env_file` для backend нет. После изменения окружения требуется пересоздание контейнера, а не только `restart`.

## Аутентификация

| Переменная | Обязательность | Значение по умолчанию | Описание | С какой версии |
| --- | --- | --- | --- | --- |
| `ENV` | Нет | `dev` | При `dev` зарегистрированы `/api/docs` и `/api/openapi.yaml`. Любое другое непустое значение меняет стандартное значение Secure-cookie на `true`; перечень значений не валидируется. | Не установлено¹ |
| `COOKIE_SECURE` | Нет | `false` при `ENV=dev`, иначе `true` | Флаг Secure у `rl_session`. В `env.example` явно записано `false`, что при прямой передаче переопределит производное значение даже с `ENV=production`. | Не установлено¹ |
| `SESSION_DURATION` | Нет | `168h` | Длительность сессии; формат `time.ParseDuration`. Задавайте положительное значение: конфигурация не отвергает нулевую и отрицательную длительность. | Не установлено¹ |
| `BOOTSTRAP_ADMIN_EMAIL` | Нет | `admin@localhost` | Используется только при пустой таблице пользователей. | Не установлено¹ |
| `BOOTSTRAP_ADMIN_PASSWORD` | Да для подстановки Compose; нет для Config | `admin` в Config; Compose требует непустое значение | Первоначальный пароль. Значение примера небезопасно. Это не механизм сброса существующего пароля. | Не установлено¹ |
| `BOOTSTRAP_ADMIN_FULL_NAME` | Нет | `Administrator` | Имя первоначального администратора. | Не установлено¹ |
| `BOOTSTRAP_ADMIN_FORCE_PASSWORD_CHANGE` | Нет | `true` | Флаг читается и журналируется, но bootstrap не записывает требование смены в БД. См. [первичную настройку](Администратор-Первичная-настройка). | Не установлено¹ |

## Обогащение и обработка импорта

| Переменная | Обязательность | Значение по умолчанию | Описание | С какой версии |
| --- | --- | --- | --- | --- |
| `ENRICHMENT_ENABLED` | Нет | `true` | Включает регистрацию и запуск планировщика внешних синхронизаций. Не отключает Redis-обработчики и работу с локальными базами. | Не установлено¹ |
| `NVD_API_KEY` | Нет | Пусто | Передаётся синхронизаторам NVD и CPE; влияет на интервалы запросов. | Не установлено¹ |
| `RL_SCANNER_KIND_OVERRIDES` | Нет | Пусто | Подсказки классификации: пары `сканер=категория` через запятую или JSON-объект. Категории: `sca`, `sast`, `dast`, `iac`, `secrets`, `other`. Некорректные пары игнорируются. | Не установлено¹ |
| `BDU_INSECURE_SKIP_VERIFY` | Нет | `true` | Прямое чтение в синхронизаторе БДУ, отсутствует в Config и `env.example`. По умолчанию проверка сертификата БДУ отключена. Для проверки сертификата явно передайте `false`. | Не установлено¹ |
| `RL_MAX_SCAN_SIZE_MB` | Нет | `50` | Прямое чтение в `api/scans.go`: ограничение тела `/api/v1/scans`, единица равна 2²⁰ байт. Не общий лимит `/api/v1/import`. | Не установлено¹ |
| `RL_MAX_SCAN_FORM_MEMORY_MB` | Нет | `8` | Порог памяти разбора multipart в `/api/v1/scans`, единица равна 2²⁰ байт; это не предел всего потребления памяти. | Не установлено¹ |

`BDU_INSECURE_SKIP_VERIFY` имеет собственный разбор: поддерживает `1/0`, `true/false`, `yes/no`, `y/n`, `on/off` без учёта регистра и с удалением краевых пробелов. Некорректное значение возвращает небезопасное значение по умолчанию. Для двух лимитов сканирования некорректное или неположительное значение заменяется стандартным.

| `SERVER_HOST` | Нет | `0.0.0.0` | Адрес HTTP-сервера. Compose передаёт фиксированное `0.0.0.0`. | Не установлено¹ |
| `SERVER_PORT` | Нет | `8080` | Внутренний порт HTTP-сервера. Compose передаёт фиксированное `8080`. | Не установлено¹ |

| `CORS_ORIGINS` | Нет | `http://localhost:3000,http://localhost:5173` | Точные origin через запятую. В Compose сформированы из localhost и порта frontend, а не прочитаны из одноимённой строки `.env`. | Не установлено¹ |
| `TRUST_PROXY` | Нет | `false` | Если `true`, извлекается первый элемент `X-Forwarded-For` без проверки доверенного отправителя. См. [безопасную сеть](Администратор-Безопасная-сетевая-конфигурация). | Не установлено¹ |
| `FRONTEND_PORT` | Нет | `3000` | Опубликованный порт frontend и подстановка в CORS. | Не установлено¹ |

## Логирование

| Переменная | Обязательность | Значение по умолчанию | Описание | С какой версии |
| --- | --- | --- | --- | --- |
| `LOG_LEVEL` | Нет | `info` | Точные значения `debug`, `warn`, `error`; остальные, включая `info`, выбирают уровень INFO. Корневой production overlay фиксирует `warn`. | Не установлено¹ |

Backend всегда использует JSON-обработчик `slog`, включая режим `dev`. Ротация задаётся драйвером журналов Compose, а не переменной backend.

| --- | --- | --- | --- | --- |
| `FRONTEND_TARGET` | Нет | `production` в Compose | Цель Dockerfile. В `env.example` — `development`; production overlay явно выбирает `production`. | Не установлено¹ |
| `VERSION` | Нет | `dev` в Compose; содержимое `VERSION` в `scripts/build.sh` | Метаданные сборки, не runtime-параметр Config. | Не установлено¹ |
| `COMMIT` | Нет | `unknown` в Compose; текущая Git-ревизия в скрипте сборки | Метаданные сборки. | Не установлено¹ |
| `BUILD_DATE` | Нет | `unknown` в Compose; текущее UTC-время в скрипте сборки | Метаданные сборки. | Не установлено¹ |
| `VITE_PROXY_TARGET` | Нет | `http://localhost:8080` в Vite | В dev Compose передаёт `http://backend:8080`; используется конфигурацией прокси Vite. | Не установлено¹ |
| `VITE_API_URL` | Нет | Задаётся Compose; в production overlay пусто | В текущем `frontend/src/api/client.ts` не используется: клиент вызывает относительные пути. | Не установлено¹ |
| `DATABASE_MAX_CONNS` | Нет | `25` в Compose | Передаётся контейнеру, но Config и серверный main её не читают. Не считайте действующей настройкой пула. | Не установлено¹ |
| `DATABASE_MIN_CONNS` | Нет | `5` в Compose | Передаётся контейнеру, но Config и серверный main её не читают. | Не установлено¹ |

Служебные скрипты имеют отдельное окружение:

| Переменная | Обязательность | Значение по умолчанию | Описание | С какой версии |
| --- | --- | --- | --- | --- |
| `APP_VERSION` | Нет | `0.1.0b` в `backup.sh` | Поле версии манифеста копии. Самостоятельно не читается из `VERSION`; передавайте версию фактической сборки. | Не установлено¹ |
| `APP_SERVICES` | Нет | `backend analysis_worker intel_worker sbom_worker sbom_transitive_worker` | Список остановки/запуска `restore.sh`; корневой Compose содержит из него только backend. Для него задайте `backend frontend`, учитывая ограничения восстановления. | Не установлено¹ |
| `POSTGRES_IMAGE` | Нет | `postgres:16-alpine` | Образ временной БД в `verify.sh`; задаётся также флагом `--postgres-image`. Последующая загрузка `.env` может переопределить значение. | Не установлено¹ |
| `REDIS_IMAGE` | Нет | `redis:7-alpine` | Образ временного Redis в `verify.sh`; задаётся также флагом `--redis-image`. Последующая загрузка `.env` может переопределить значение. | Не установлено¹ |
| `NO_COLOR` | Нет | Не задана | Непустое значение отключает цветные сообщения скриптов сборки и резервного копирования. | Не установлено¹ |
| `SEED_FINDINGS_COUNT` | Нет | `100000` | Только `cmd/seed`: число тестовых находок; некорректное или неположительное значение заменяется стандартным. Не настройка сервера и не оценка его вместимости. | Не установлено¹ |

`POSTGRES_USER` и `POSTGRES_DB` в скриптах копирования также имеют стандартное значение `redlycoris`; пароль временного PostgreSQL в `verify.sh` по умолчанию — `redlycoris`. Это не пароль основного сервера. Параметры генератора тестовых данных не являются настройками эксплуатируемого backend.

`HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` не входят в Config и не передаются штатным Compose. Нельзя обещать единое поведение прокси всем источникам: NVD создаёт собственный `http.Transport` без `Proxy`, БДУ клонирует стандартный транспорт, остальные используют стандартный транспорт. Подробнее — [закрытый контур](Администратор-Работа-в-закрытом-контуре).

## Расхождения и проверка применения

| Расхождение | Последствие |
| --- | --- |
| `ENV`, `COOKIE_SECURE`, `TRUST_PROXY`, `SESSION_DURATION`, `RL_SCANNER_KIND_OVERRIDES` есть в примере, но не передаются штатным Compose | Изменение только `.env` не меняет соответствующие поля backend |
| `DATABASE_URL`, `REDIS_URL`, `SERVER_HOST`, `SERVER_PORT` из `.env` не подставляются в backend | Действуют значения `environment` из Compose |
| `CORS_ORIGINS` в примере закомментирована | Даже после раскомментирования Compose не использует эту подстановку |
| Дополнительные `BDU_INSECURE_SKIP_VERIFY` и `RL_MAX_SCAN_*` отсутствуют в двух основных источниках | При необходимости задайте их непосредственно в `services.backend.environment` |
| `BOOTSTRAP_ADMIN_FORCE_PASSWORD_CHANGE=true` | Не гарантирует смену bootstrap-пароля |
| Заявленные в Compose параметры пула | Не читаются серверным кодом |

1. Добавьте необходимые подстановки в локальный overlay. Для выбранного набора файлов выполните `docker compose ... config --quiet`; многоточие замените фактическими флагами `-f`, а не копируйте буквально.
2. Пересоздайте backend командой `docker compose ... up -d --no-deps --force-recreate backend`. Перед этим учтите краткую недоступность API и прерывание фоновых задач.
3. Выведите только несекретные поля:

   ```bash
   docker inspect redlycoris-backend --format '{{range .Config.Env}}{{println .}}{{end}}' |
     grep -E '^(ENV|COOKIE_SECURE|TRUST_PROXY|SESSION_DURATION|ENRICHMENT_ENABLED|LOG_LEVEL|CORS_ORIGINS|BDU_INSECURE_SKIP_VERIFY)='
   curl --fail --silent --show-error http://localhost:8080/readyz
   ```

Проверка результата: указанные переменные присутствуют с заданными значениями, API возвращает `status: ready`. Отсутствие строки в окружении означает использование значения кода по умолчанию, а не пустого значения. Не выводите полный `docker inspect` или развёрнутую конфигурацию Compose в общедоступные журналы.
