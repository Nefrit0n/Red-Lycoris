# Интеграции-API-токены

Для CI используйте PAT проекта вида `rl_pat_<prefix>_<secret>` в заголовке `Authorization: Bearer <token>`. PAT хранит собственные scopes и ID проекта. Он не является универсальным токеном организации и не выбирает проект по `project_key`.

## Типы и назначение

| Механизм | Назначение и ограничения |
|---|---|
| PAT проекта | CI-загрузка и доступ к своему скану; выпуск и отзыв через API токенов проекта |
| Пользовательская сессия | Cookie `rl_session` или поддержанный сессионный bearer; пользовательский RBAC, ручной импорт и управление PAT |
| `POST /projects/{id}/ingest-token` | Заглушка: выдаёт случайную строку без сохранения; не используйте её для загрузки |

Секрет PAT генерируется из 32 случайных байт. В БД хранится SHA-256 секрета, сравнение при аутентификации выполняется за постоянное время. Полное значение возвращается только при создании. Не путайте PAT Red Lycoris с PAT GitHub или GitLab.

## Права и ограничения

| Операция | Кто может выполнить |
|---|---|
| Посмотреть список PAT проекта | Пользователь с ролью `viewer` или выше; глобальный администратор |
| Создать и отозвать PAT | `project_admin` проекта или глобальный администратор, с пользовательской сессией |
| Загрузить скан | PAT со scope `scans:write` |
| Получить скан по ID | PAT этого проекта; отдельный scope в обработчике не проверяется |

API выпуска принимает scopes `scans:write` и `findings:read`. Второй присутствует в интерфейсе, но маршруты чтения находок не подключают `RequireScope("findings:read")` и используют пользовательский RBAC. Не рассчитывайте на полноценный доступ PAT к каталогу находок только по этому scope.

| Ограничитель | Реализация |
|---|---|
| Срок | Положительное `expires_in_days` задаёт срок от момента выпуска; отсутствие, `null`, ноль и отрицательное значение не задают срок |
| Выбор срока в UI | 30 дней, 90 дней, без срока; первоначально выбраны 30 дней |
| Квота PAT на проект | В обработчике выпуска и таблице не задана |
| Квота сканов/находок на PAT | Не реализована |
| Rate limit PAT | На маршруте загрузки отдельного ограничителя нет; ограничения входа пользователя к PAT не относятся |
| Размер отчёта | Лимит multipart из `RL_MAX_SCAN_SIZE_MB`; см. [контракт загрузки](Интеграции-Обзор) |
| Последнее использование | Записывается асинхронно, не чаще раза в минуту на токен в процессе; это не журнал каждого запроса |

Проверка PAT читает его отзыв и срок из БД, но не проверяет активность создавшего пользователя. Деактивация пользователя не заменяет отдельный отзыв выпущенных им PAT.

## Выпуск

1. Войдите как `project_admin` или глобальный администратор. Откройте настройки проекта и блок «API токены проекта».
2. Нажмите «Создать токен», укажите назначение, выберите `scans:write` и срок.
3. Сохраните показанный токен в секрете CI. Полное значение после закрытия диалога повторно получить нельзя.

Проверка: новый PAT виден в списке с нужными scopes и сроком. Выполните тестовую загрузку по [шаблону CI](Интеграции-GitLab-CI); должен вернуться HTTP 200 с `data.scan_id`, а запрос скана с тем же PAT должен показать `status: completed` и ожидаемый проект.

При автоматизации управления используйте пользовательскую сессию:

| Запрос | Тело или ответ |
|---|---|
| `GET /api/v1/projects/{id}/api-tokens` | `data[]`, `meta.total`; возвращаются и отозванные токены, без секрета |
| `POST /api/v1/projects/{id}/api-tokens` | `{"name":"gitlab-main","scopes":["scans:write"],"expires_in_days":30}`; HTTP 201, секрет в `data.token`, ID в `data.id` |
| `DELETE /api/v1/projects/{id}/api-tokens/{tokenID}` | HTTP 200, `{"data":{"status":"revoked"}}` |

## Ротация и отзыв

1. Выпустите новый PAT с теми же необходимыми правами и конечным сроком.
2. Замените секрет CI и запустите загрузку. Проверьте скан по возвращённому ID.
3. Перед отзывом учтите: использующие старое значение задания потеряют доступ. В списке PAT нажмите «Отозвать» и подтвердите действие.

Проверка: включите «Показать отозванные», убедитесь в наличии `revoked_at` через API списка. Выполните `GET /api/v1/scans/{scan_id}` со старым PAT: ожидается HTTP 401 `UNAUTHORIZED`; с новым — HTTP 200. Ответ DELETE сам по себе недостаточен: обработчик не сообщает, нашёл ли он строку по переданному ID.

## Компрометация

1. Немедленно отзовите скомпрометированный PAT; для этой процедуры приоритет имеет прекращение доступа, даже если задания CI временно завершатся ошибкой.
2. Проверьте сканы целевого проекта, сведения о создателе PAT и доступные журналы за предполагаемый период компрометации. `last_used_at` не позволяет восстановить все обращения.
3. Удалите раскрытое значение из доступных логов и настроек CI, устраните источник утечки и выпустите новый PAT.

Проверка: старый PAT получает 401, новый выполняет тестовую загрузку, в настройках CI используется новое значение. Не выводите PAT через `echo`, трассировку shell или отладочный вывод HTTP.
