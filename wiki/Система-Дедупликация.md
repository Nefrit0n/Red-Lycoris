# Система-Дедупликация

Дедупликация выполняется при записи в PostgreSQL по уникальному полю `findings.fingerprint`. Это точное совпадение нормализованного набора полей, а не поиск семантически похожих находок. Группировка строк в интерфейсе не является дедупликацией.

## Формула fingerprint

`CalculateFingerprint` формирует строку конкатенацией следующих значений строго в указанном порядке, **без разделителей**, затем вычисляет SHA-256 от её байтов UTF-8. Результат — шестнадцатеричная строка в нижнем регистре.

| Позиция | Значение | Нормализация | Что различает |
|---|---|---|---|
| 1 | `Kind` | Десятичная запись: SCA `0`, SAST `1`, DAST `2`, IaC `3`, secrets `4`, other `5` | Категории находок |
| 2 | `RuleID` | Нижний регистр; `nil` превращается в пустую строку | Правила сканера |
| 3 | Первый элемент `CVEIDs` | Нижний регистр; пустой массив даёт пустую строку | Первую CVE |
| 4 | `FilePath` | Нижний регистр | Расположение в файле |
| 5 | `LineStart` | Десятичная запись, включая `0` | Начальную строку |
| 6 | `LineEnd` | Десятичная запись, включая `0` | Конечную строку |
| 7 | Первый элемент `CWEIDs` | Десятичная запись; пустой массив даёт `0` | Первую CWE |
| 8 | `Component` | Нижний регистр | Компонент |
| 9 | `ComponentVersion` | Нижний регистр | Версию компонента |

```text
fingerprint = hex_lower(SHA256(UTF8(
    decimal(kind)
    + lower(rule_id_or_empty)
    + lower(first_cve_or_empty)
    + lower(file_path)
    + decimal(line_start)
    + decimal(line_end)
    + decimal(first_cwe_or_zero)
    + lower(component)
    + lower(component_version)
)))
```

Сама функция не удаляет пробелы, не сортирует массивы CVE/CWE и не нормализует разделители пути. Предварительные преобразования зависят от парсера. Если детектор меняет категорию `other` на уточнённую, он пересчитывает fingerprint. Обработчики импорта вычисляют его, если парсер оставил поле пустым.

## Повторный импорт

Оба пути записи, `Create` и `CreateTx`, выполняют `INSERT ... ON CONFLICT (fingerprint) DO UPDATE`. При конфликте возвращается ID существующей находки.

| Поле или действие | Поведение при совпадении |
|---|---|
| `last_seen` | Заменяется значением из повторно импортируемой находки; это не `GREATEST` со старым значением |
| `times_seen` | Увеличивается на единицу за каждый обработанный элемент, а не за уникальный скан |
| `secret_fingerprint` | Заменяется входным значением, если оно не `NULL`; иначе сохраняется старое |
| `first_seen`, `project_id`, `source_type` | Не меняются |
| Название, описание, severity, статус, назначение, сведения о закрытии | Не меняются |
| Остальные поля, включая `commit_sha` и исправленную версию | Не обновляются этой операцией |
| Ручной импорт | Увеличивается `updated`; событие `seen_again` ограничено уникальным индексом по находке и дню UTC |
| CI-загрузка | Создаётся связь со сканом в `finding_scan_links`, учитывается `updated` |
| Повторное обогащение | При ручном импорте в очередь идут только новые находки; при CI-загрузке — все находки скана |

Повторное обнаружение не открывает закрытую находку автоматически. Отсутствие находки в следующем отчёте также не закрывает её: в обработчике загрузки нет такого сравнения наборов.

Ручной импорт сохраняет элементы независимо и может завершиться частично. CI-загрузка сохраняет находки, связи и запись скана в одной транзакции. Повторяющиеся элементы внутри одного отчёта не превращают импорт в идемпотентную операцию по счётчику `times_seen`.

## Область уникальности и ограничения

`project_id` не входит в формулу, а ограничение `UNIQUE (fingerprint)` действует на всю таблицу. Поэтому одинаковый fingerprint в разных проектах обновляет одну находку, оставляя её в исходном проекте. CI-скан другого проекта может получить связь с этой же находкой: схема не проверяет равенство проектов в `finding_scan_links`. Проектные проверки доступа не превращают такой ключ в изолированную дедупликацию по проектам.

| Ограничение | Следствие |
|---|---|
| Только первые CVE и CWE | Изменение порядка массива может изменить ключ; дополнительные идентификаторы не участвуют |
| Номера строк входят в ключ | Сдвиг кода может создать новую находку |
| Регистр пути игнорируется | Разные пути на регистрозависимой файловой системе могут совпасть |
| Строки соединяются без разделителей | Разные наборы полей могут дать одинаковую строку ещё до SHA-256; например, пары строк `1, 23` и `12, 3` при прочих равных дают `123` |
| Нет URL, HTTP-метода и параметра, IaC-ресурса, значения секрета | Различия только в этих данных не разделяют находки |
| Нет `source_type`, названия и описания | Разные сканеры могут объединиться, если участвующие поля совпадают |
| Нет устойчивой привязки к фрагменту кода | Алгоритм не отслеживает перемещение или переименование объекта |

Эти ограничения следуют из сериализации входных полей, а не из предположения о криптографической коллизии SHA-256.

## Отдельный fingerprint секрета

`secret_fingerprint` предназначен для сопоставления значений секретов, в том числе при группировке. Он не заменяет уникальный `fingerprint` находки.

```text
secret_fingerprint = hex_lower(SHA256(UTF8(lower(trim(kind)) + ":" + value)))
```

В `ComputeSecretFingerprint` значение `value` не приводится к нижнему регистру. Gitleaks и TruffleHog предварительно удаляют крайние пробелы выбранного значения. Путь и строки файла в этот отдельный хеш не входят. Индекс `idx_findings_secret_fingerprint` не уникален и охватывает только ненулевые значения.

Хеш не является шифрованием секрета и не гарантирует обезличивание остальных полей отчёта. Границы защиты описаны в [модели безопасности](Система-Модель-безопасности).
