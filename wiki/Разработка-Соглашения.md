# Разработка-Соглашения

Эта страница содержит правила, необходимые при внесении изменений. Описания текущей реализации, параметры окружения и API сверяйте с кодом и соответствующими страницами Wiki; соглашение не заменяет их.

## Общие правила

Не добавляйте зависимость без необходимости и явного согласования. Не создавайте абстракцию «на будущее»: интерфейс вводится, когда требуется не менее двух реализаций. Один запрос на изменение оформляйте одним логическим коммитом с осмысленным сообщением.

Комментарии объясняют причину решения, а не пересказывают код. Ошибки оборачивайте с контекстом, например `fmt.Errorf("storage.FindByID: %w", err)`. Не вводите глобальные переменные для зависимостей: передавайте их в конструкторы.

Проверьте результат: diff не содержит неиспользуемых зависимостей, временных файлов и несвязанных правок; сообщение коммита описывает одно изменение.

## Backend Go

| Область | Соглашение |
|---|---|
| HTTP | Используйте `net/http` и Chi. Handler получает `http.ResponseWriter` и `*http.Request`, разбирает вход, вызывает прикладной код и возвращает JSON |
| Ошибки API | Возвращайте контролируемую ошибку через helper ответа, не допускайте panic как обычного пути |
| SQL | Используйте `pgx/v5` и явный SQL. ORM и генерация запросов не применяются |
| Запросы | Не используйте `SELECT *` и OFFSET; выбирайте необходимые колонки, применяйте курсор и индексируемые условия |
| Контекст | Передавайте `context.Context` через слои, учитывайте отмену и таймауты |
| Хранилище | Используйте переданный `pgxpool.Pool`, не создавайте пул в обработчике |
| Конфигурация | Читайте настройки через существующую `config.Config`; не добавляйте скрытые константы вместо env-переменной |
| Логирование | Используйте структурированный `slog` и не записывайте секреты в поля лога |
| Миграции | Изменения схемы оформляйте парой SQL-файлов в `backend/migrations` |

Проверьте результат: запрос явно перечисляет колонки и не содержит OFFSET; ошибка имеет контекст; тесты пакета проходят.

## Frontend

| Область | Соглашение |
|---|---|
| Компоненты | Используйте функциональные компоненты и хуки |
| Серверное состояние | Загружайте и изменяйте данные через TanStack Query; не заменяйте это `useEffect` с `fetch` |
| Клиентское состояние | Используйте существующие Zustand stores только для клиентского состояния |
| Таблицы | Используйте TanStack Table; для длинных плоских списков сохраняйте виртуализацию TanStack Virtual |
| Стили | Используйте Tailwind и компоненты shadcn/ui, не добавляйте CSS-in-JS |
| Типы | Сохраняйте TypeScript strict и не вводите `any` |
| Текст интерфейса | Пользовательские строки пишите по-русски |
| Форматы | Даты форматируйте через `date-fns`, числа — через `Intl.NumberFormat` |

Проверьте результат: `npm run lint`, типовая проверка и тесты frontend проходят, а пользовательская строка не появляется на английском без технической необходимости.

## Тесты и проверка изменений

Для доменной логики добавляйте table-driven тесты рядом с исходным файлом. Интеграционные тесты с testcontainers добавляйте, когда изменение требует проверки взаимодействия с инфраструктурой. Перед передачей изменения выполните проверки, относящиеся к затронутым компонентам; полный перечень приведён в [тестировании](Разработка-Тестирование).

Проверьте результат: новый сценарий либо покрыт автоматическим тестом, либо ограничение тестирования объяснено в описании изменения.
