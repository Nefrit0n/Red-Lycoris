# Пользователь-Импорт-результатов

Страница «Импорт» принимает подготовленные файлы отчётов в выбранный проект. Она не запускает сканеры и не заменяет API приёма сканов из CI. Для загрузки требуется роль «Триаж», администратор проекта либо глобальный администратор.

## Файлы и определение формата

В окне выбора доступны расширения `.json` и `.sarif`. Область перетаскивания также принимает файлы с MIME-типом `application/json`. Формат определяется содержимым, а не названием файла; ручного переключателя парсера на странице нет.

| Входные данные | Предварительная обработка в браузере | Обработка на сервере |
|---|---|---|
| SARIF | Метка SARIF; для части документов доступен предварительный счётчик | Разбор SARIF |
| Gitleaks JSON | Метка Gitleaks при совпадении признаков первого элемента | Разбор Gitleaks |
| TruffleHog JSON или NDJSON | Метка TruffleHog при совпадении структуры | Разбор TruffleHog |
| Универсальный JSON | Массив либо объект с массивом `findings` получает предварительную метку универсального JSON | Проверка универсального формата и полей находок |
| Trivy, Grype, Semgrep, gosec, Checkov, OWASP ZAP в JSON | Метка может быть неизвестной либо универсальной: отдельных детекторов этих форматов в форме нет | Доступны соответствующие парсеры |

Неизвестная предварительная метка не блокирует отправку синтаксически корректного JSON. Ошибка разбора JSON в браузере исключает файл из загрузки. Для TruffleHog NDJSON используйте файл с расширением `.json`: расширение `.ndjson` не включено в окно выбора.

Серверный детектор также содержит парсер AppScreener, но это не означает, что страница «Импорт» принимает любой его входной контейнер: браузер предварительно требует JSON либо распознаваемый TruffleHog NDJSON.

Обработчик импорта читает не более 50 МиБ тела одного запроса. Проверки размера на этой странице нет; превышение обрезает читаемые данные и может проявиться как ошибка парсера, а не отдельное сообщение о размере. Ограничения reverse proxy могут быть строже.

## Загрузка отчётов

Роль: триаж и выше в целевом проекте.

1. Откройте «Импорт». Перетащите файлы в область «Файлы» или нажмите на неё для выбора. До запуска удалите ошибочно добавленные файлы кнопкой «×» в соответствующей строке.
2. Проверьте имена и предварительные метки. Файлы с ошибкой JSON исправьте и добавьте заново.
3. В поле «Целевой проект» выберите проект. Список может содержать проекты, где у вас есть только просмотр: для импорта этого недостаточно.
4. Нажмите «Импортировать». Файлы отправляются последовательно, каждый — отдельным запросом. Индикатор показывает номер обрабатываемого файла, а не долю сохранённых находок.
5. Дождитесь блока «Импорт завершён» и проверьте результат каждого файла.

Проверка результата: для каждого файла показаны фактически определённый сервером формат, число импортированных и обновлённых записей, ошибки при их наличии. Затем откройте «Находки», выберите тот же проект и найдите контрольную запись из отчёта. Надпись «Импорт завершён» сама по себе не подтверждает отсутствие ошибок.

## Создание проекта из формы импорта

Роль: любой аутентифицированный пользователь после обязательной смены пароля. Новый проект предоставляет создателю права администратора проекта.

1. В списке «Целевой проект» выберите «+ Создать новый проект».
2. Введите название и, при необходимости, описание. Нажмите «Создать».

Проверка результата: диалог закрывается, новый проект выбран как целевой. После этого выполните процедуру загрузки отчётов выше.

## Значение результатов

| Поле результата | Интерпретация |
|---|---|
| Импортировано | Созданы новые находки |
| Обновлено | Входные находки сопоставлены с существующими записями при сохранении |
| Ошибки | Отдельные записи не прошли проверку или не сохранились; ошибка запроса также выводится в этом блоке |
| Индекс `#` | Индекс записи из серверного результата; для ошибки целого файла форма использует 0 |

Импорт не атомарен для всего набора файлов или всего отчёта: корректные записи могут сохраниться одновременно с ошибками других записей. Интерфейс раскрывает первые пять ошибок каждого файла и показывает количество оставшихся. Не повторяйте загрузку вслепую после сетевого сбоя: часть данных уже могла сохраниться.

Для новых находок сервер отдельно публикует задание на обогащение. Завершение импорта не означает завершения обогащения. Эта форма не создаёт записи для вкладки проекта «Сканы» и не передаёт ветку, коммит или URL задания CI.

## Устранение ошибок и повтор

Роль для повторной загрузки: триаж и выше. Проверить уже сохранённые находки может роль просмотра и выше.

| Симптом | Причина по реализации | Действие |
|---|---|---|
| Файл не появился в списке | Не соответствует фильтру расширения или MIME-типа | Используйте поддерживаемый JSON/SARIF; не переименовывайте архив в JSON |
| Ошибка JSON до запуска | Браузер не разобрал содержимое | Проверьте полноту файла и его формат |
| Кнопка импорта недоступна | Нет выбранного проекта, нет файлов без ошибок либо идёт импорт | Выберите проект и исправьте файлы; дождитесь текущей операции |
| Отказ в доступе | В проекте отсутствует роль триажа или выше | Запросите нужную роль у администратора проекта |
| Ошибка парсера | Сервер не распознал содержимое либо не смог его разобрать | Проверьте экспорт сканера, размер и соответствие поддерживаемому формату |
| Нет находок во входных данных | Парсер вернул пустой результат | Проверьте отчёт; для Grype пустой результат допускается |
| Сетевая ошибка | Форма не получила или не смогла обработать ответ | Сначала проверьте находки целевого проекта, затем повторите загрузку при необходимости |

1. Проверьте контрольные записи в целевом проекте и устраните причину ошибки.
2. Нажмите «Импортировать ещё», добавьте исправленные файлы и снова проверьте целевой проект.
3. Выполните импорт.

Проверка результата: в новом результате отсутствуют прежние ошибки, ожидаемые записи доступны в проекте. При повторном поступлении совпадающих находок возможен рост счётчика «Обновлено», а не «Импортировано».
