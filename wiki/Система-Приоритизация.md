# Система-Приоритизация

`priority_score` — вычисляемая при обогащении оценка в диапазоне от 0 до 10. Она хранится в обычной таблице `finding_scores`, а не в materialized view. Обновление справочника само по себе не пересчитывает все ранее сохранённые оценки.

## Формула

Ниже приведена фактическая формула `CalculatePriorityScore`, включая нормализацию и дополнительные вклады KEV, тренда EPSS и исправлений OSV.

```text
recency = 10 × exp(-daysOld / 365)

raw = baseScore × 0.30
    + epssScore × 100 × 0.25
    + (kevBonus + urgencyBonus) × 0.20
    + bduVal × 0.10
    + recency × 0.10
    + 5 × 0.05
    + trendBonus × 0.05
    + fixBonus × 0.03

priority_score = min(10, max(0, round(raw / 33.25 × 10 × 100) / 100))
```

Округление выполняется `math.Round` до двух десятичных знаков, затем применяется ограничение диапазона. Делитель `33.25` — фиксированная константа, не динамическая сумма максимумов. С учётом всех бонусов `raw` может превысить её, тогда результат ограничивается значением `10`.

| Слагаемое | Вход и правило | Вклад в `raw` |
|---|---|---|
| CVSS | `baseScore` из NVD; в одной записи приоритет v4.0, затем v3.1, затем v2 | `baseScore × 0.30` |
| EPSS | `epssScore` в долях, не percentile | `epssScore × 25` |
| KEV | `kevBonus = 10`, если `isKEV`; дополнительно `+5`, если `kevRansomware` | `(kevBonus + urgencyBonus) × 0.20` |
| БДУ | `bduVal = 5` при совпадении с БДУ, иначе `0` | `0.50` либо `0` |
| Давность | `recency = 10 × exp(-daysOld / 365)` | От `1` при нулевом возрасте с экспоненциальным уменьшением |
| Exposure | Константа `5` внутри функции | Всегда `0.25` |
| Тренд EPSS | `trendBonus = 5`, только если `epssTrend7d > 0.10` | `0.25` либо `0`; равенство `0.10` бонуса не даёт |
| Исправление OSV | `fixBonus = 2`, если в сопоставленных данных OSV найдено исправление | `0.06` либо `0` |

В функции бонус ransomware добавляется по отдельному флагу, без дополнительной проверки `isKEV`; в штатном pipeline этот флаг извлекается из найденных записей KEV.

### Срочность KEV

При `isKEV = false` `urgencyBonus` равен нулю. В остальных случаях используется минимальное число дней до `due_date` среди совпавших записей KEV.

| `daysUntilKevDue` | `urgencyBonus` |
|---|---:|
| Меньше `0` | 7 |
| От `0` до `6` включительно | 5 |
| От `7` до `29` включительно | 3 |
| От `30` до `89` включительно | 1 |
| `90` и больше; нет подходящей даты | 0 |

### Давность и exposure

Pipeline передаёт `daysOld = max(0, время с findings.first_seen в часах / 24)`. Это возраст находки в платформе, **не время с публикации CVE**. При возрасте 365 дней `recency ≈ 3.678794`, а её вклад в `raw ≈ 0.367879`.

Настройки exposure на уровне проекта в текущей реализации нет: параметр отсутствует в аргументах функции и в схеме проекта, значение всегда `5`. Комментарий о конфигурируемости не подкреплён исполняемым кодом. Видимость проекта, SLA и параметры репозитория не участвуют в формуле.

## Подготовка входных данных

| Данные | Фактический выбор в `EnrichFinding` |
|---|---|
| CVE | Идентификаторы нормализуются и используются для поиска в локальных таблицах |
| CVSS при нескольких CVE | `baseScore` перезаписывается при обработке очередной записи с CVSS. SQL не задаёт порядок; максимум по CVE не вычисляется |
| EPSS | Берётся максимальный текущий score среди совпавших CVE; percentile и семидневный тренд относятся к выбранной записи |
| Тренд | `ComputeTrend` сравнивает последнюю точку истории с последней точкой не позднее чем за 7 дней до неё; при отсутствии такой точки тренд равен нулю |
| KEV | Признак наличия, объединённый признак ransomware и минимальный срок среди совпадений |
| БДУ | Признак наличия совпадения по CVE; CVSS из БДУ не заменяет `baseScore` |
| OSV | Сначала совпадения CVE с `aliases`, затем резервный поиск по экосистеме и имени пакета. Наличие фиксированной версии в разобранных диапазонах даёт `osvHasFix` |

Признак OSV не доказывает, что исправление применимо к установленной версии: резервное сопоставление не проверяет вхождение версии компонента в уязвимый диапазон. Поле `findings.fixed_version` само по себе не является входом бонуса OSV.

Число дней до срока KEV вычисляется как `int((due_date - now).Hours() / 24)`, с усечением к нулю. Поэтому просрочка меньше суток ещё даёт `0`, а не отрицательное значение. Это отличается от сравнения календарных дат.

Начальные числовые значения и флаги обогащения нулевые. Если совпадений нет, это не запрещает запись оценки: вклад давности и exposure остаётся. Поэтому ненулевой `priority_score` не доказывает наличие сведений CVSS или EPSS.

## Пример расчёта

Для находки с идентификатором **CVE-2021-44228** ниже задан условный набор входов. Идентификатор используется в тестовых данных репозитория; числа выбраны для демонстрации формулы и **не являются утверждением об актуальных данных этой CVE**.

| Вход | Условное значение |
|---|---:|
| `baseScore` | 9.8 |
| `epssScore` | 0.80 |
| `epssTrend7d` | 0.12 |
| `isKEV` | `true` |
| `kevRansomware` | `false` |
| `daysUntilKevDue` | 10 |
| `isBDU` | `true` |
| `osvHasFix` | `true` |
| `daysOld` | 365 |

```text
kevBonus     = 10
urgencyBonus = 3
recency      = 10 × exp(-1) ≈ 3.678794
trendBonus   = 5
fixBonus     = 2

raw = 2.94 + 20 + 2.60 + 0.50 + 0.367879 + 0.25 + 0.25 + 0.06
    ≈ 26.967879

priority_score = round(26.967879 / 33.25 × 10 × 100) / 100
               = 8.11
```

Для проверки воспроизводимости достаточно подставить эти аргументы в `CalculatePriorityScore`: ожидаемый результат — `8.11`. В реальном pipeline возраст и срок KEV зависят от времени расчёта, а входы — от состояния локальных справочников.

## Хранение и актуальность

При обогащении запись `finding_scores` обновляется по `finding_id`: сохраняются CVSS, EPSS, percentile, признаки KEV/БДУ, итог и `calculated_at`. Все промежуточные бонусы и полный снимок аргументов в этой таблице не сохраняются. Восстановить прежний расчёт только по ней после изменения справочников нельзя.

Синхронизация справочников и пятиминутное обновление materialized views не запускают пересчёт сохранённых оценок. Повторная CI-загрузка отправляет находки скана на обогащение, а ручное действие обогащения обрабатывает выбранную находку. Массовое `enrich-all` выбирает только находки без строки в `finding_scores`, не все устаревшие оценки. Подробности — [обогащение](Система-Обогащение).

Сводные поля списка не полностью совпадают с входами сохранённого priority: например, `max_cvss` в запросе списка — максимум `cvss_v31_score` из текущей NVD, тогда как расчёт приоритета предпочитает v4.0 и при нескольких CVE не вычисляет максимум. Сопоставлять эти значения как один и тот же показатель нельзя.
